### 提供方法

利用者が実績一覧または共通フッターの「業務実績資料（PDF）をダウンロード」を押した時だけ、同じサイトのbase64ファイルを取得します。ページを表示しただけではPDFデータを取得しません。

ブラウザ内でPDFへ復元し、サイズとPDFヘッダーを確認します。Web Cryptoが使える環境ではSHA256も照合します。正常な内容のみを `application/pdf` のBlobとして保存し、ダウンロード名は最新版の `業務実績説明資料_24件_A4横_v2.2.pdf` を使用します。取得・検証が済んだPDFはページを開いている間だけ再利用します。保存用Object URLは開始後60秒またはページを離れる際に解放します。

処理中は2か所のボタンを無効にし、進行状況を表示します。45秒以内に取得が完了しない場合や、ネットワーク・照合エラー時は再試行できる状態へ戻ります。読み上げ用の通知は全ページ共通の1か所へまとめています。

配布資料には、本人の指示に基づいて不要な断り書き・段階注記を削除した修正版PDFを使用します。Web掲載31件と、資料の主要24件・全29ページはそれぞれの収録範囲です。

### PDFを更新する手順

1. 新しいPDFのページ数・ファイルサイズ・内容を確認します。
2. Python標準ライブラリなどで元PDFをbase64化し、1行と末尾LF 1文字の形式で `downloads/` 内へ保存します。PDFの内容は書き換えません。
3. `index.html` 末尾の `id="pdf-download-handler"` にある `pdf` 定義の `path`・`filename`・`byteLength`・`sha256` を新しい資料に合わせます。
4. 実績一覧とフッターのページ数・サイズ表示、資料の主要件数、READMEの資料情報を更新します。
5. base64を戻したファイルが元PDFとバイト単位で一致すること、JavaScript構文、両方のボタンで保存と再試行ができることを確認します。
6. base64ファイルを先に公開し、次に対応する `index.html` を反映します。公開後にダウンロードしたPDFのサイズとSHA256を再照合します。別名の資料へ更新する場合は、HTML反映が完了するまで旧ファイルを保持します。

同じbase64ファイル名を更新する場合も、資料の差替えと `pdf` 定義の更新を一組で管理してください。期待値と合わない内容は利用者へ配布しません。PDF取得は通常のHTTPS配信を前提とし、HTMLを端末から `file:` で直接開く場合はブラウザの制限により利用できないことがあります。
